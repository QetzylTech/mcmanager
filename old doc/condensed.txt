Technical Specification Reference: MC Manager Core Contracts

1. Architecture §0: BINDING_CONSTRAINTS

* MODULAR_MONOLITH :: One authoritative control plane, zero microservices.
* MULTI_WORLD :: Concurrent independent world instances; operations never block unrelated instances except via shared storage guard.
* NO_SYSTEMD :: Zero dependency on systemd or journalctl; functional on any Java/Python-compliant OS.
* PORTABLE_PROCESS_CONTROL :: Data-driven argv launch (no shell/double-fork); supervised via ProcessControlPort.
* IDLE_CPU_THRESHOLD :: < host-reference threshold (5-min avg) during zero state-change/stream activity.
* BASELINE_MEMORY :: Manager process within documented range, excluding managed MC processes.
* ZERO_TRUST_SECURITY :: Mandatory server-issued session authentication and server-side authorization for all requests.
* REAL_TIME_SSE :: Shared server-side streams; compute-once fan-out; zero client-side polling.
* AUDIT_GUARDRAILS :: Immutable audit/event history, durable Operations, and storage safety guards.
* TESTABLE_FAILURE_CRITERIA :: Constraint violations (e.g., Linux-only control, cross-world interference) must trigger Doc 13 test failures.

3. Document 11 §3.1 & §6: Concurrency and Operational Logic

3.1 World-Scoped Mutual-Exclusion Matrix

Requested Operation	Backup Running	Restore Running	Cleanup Running	Start/Stop/Kill
Backup	Q	R	R	A/Q

Symbols: Q (Queue/Single-flight), R (Reject), A (Allowed), A/Q (Allowed, but Stop/Kill queues behind Backup).

3.2 Operational Priority

Manual (User-initiated) > Safety-Critical (Emergency Stop/Cleanup) > Default (Backup > Restore > Cleanup)
