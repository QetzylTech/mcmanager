MCMANAGER CORE REALIGNMENT PLAN
================================================================================
Date: 2026-11-03
Scope: Bring core/ into compliance with docs/ (Documents 4–14, ARCHITECTURE.md,
       wbs.txt) with gate1–gate5_pseudocode.txt as the algorithm/API checklist.

How to read this file
---------------------
Each gate has: current verdict, MATCH/PARTIAL/MISSING/DIVERGENT vs the
corresponding gate*_pseudocode.txt, then ordered actions (must-fix vs later).

Precedence when sources disagree (ARCHITECTURE.md §5):
  1. Doc 9 wins on locking / queue / preempt / optimistic concurrency.
  2. Doc 14 wins on Minecraft adaptation (readiness, EULA, properties, RCON, save).
  3. Higher numbered document otherwise wins.
  4. ARCHITECTURE.md is reference-only and does not override numbered docs.
  5. WBS file-scope paths (src/mcmanager/...) are superseded by Doc 12
     (app/ under the application tree). core/ is the application tree;
     keep the package as app/, not src/mcmanager/.
  6. Gate pseudocode is the implementation checklist. If it conflicts with a
     numbered doc, implement the numbered doc and then update the pseudocode
     so they stop drifting. Do not invent a third design.

Do not treat core/STATUS.md as the target. It is a prior-session snapshot
and is already stale relative to this audit.

    - PID reuse guard on every signal (C7) — identity_matches exists;
      ensure terminate/send_signal always call it.
    - stdin stop path for graceful Minecraft stop (C2) — write_stdin exists;
      WorldsService Stop must use it before OS terminate.

  (infrastructure/minecraft/readiness.py + ports/minecraft.py).
  EULA detect/accept/provision exist; accept is the only true writer

  Gaps:
    - starting -> running MUST require the variant's highest applicable
