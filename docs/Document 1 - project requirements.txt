Document 1: Program Requirements (Legacy)

- Historical/legacy reference (Doc 10 §1). Only non-superseded requirements are stated below; fully superseded sections are one-line pointers. Where §N below is a pointer, later documents govern.
- Sole residual facts retained from superseded sections: none — see the §3 pointer note (later docs restate both facts).

1. Live Metrics
- Required broadcast set (SSE, JSON, push-only — no polling): RAM, CPU/core, CPU freq, storage %, MC status, rcon players, tick time, auto-stop timer, backup status, last backup, next backup, backups folder, console logs, backup logs, panel activity log, panel error log, backup count, stale-worlds count, cleanup last run, cleanup rule version, schedule version, rule last changed by, next run, missed-run count.
- MetricsCadence: IF clients=0 AND server=off THEN null; IF server=on THEN 15s_cache; IF clients>=1 THEN 1Hz_stream (logs arrive as emitted).
- Shell owns shared state; pages own nothing. Multi-tab: per-tab independent connections to shared streams; no election/heartbeat/forwarding (Doc 2 §7.1, Doc 3 §4.3).

2. Server Runs & Status — Superseded → Doc 6 §2.3 (state machine), Doc 2 §2.1/§8.1 (start-no-password, stop-password), Doc 11 §1.2 (storage guard).

3. Backup & Restore — Superseded → Doc 6 §2.3/§2.5 (off-only restore, pre_backup_state resume, corrupted-backup revert, retention), Doc 8 BackupService/RestoreService (§2, §4.3), Doc 11 §3.1/§1.2. Post-supersession residual facts (no-dedicated-undo; corrupted-restore reverts) are restated in Doc 8 §8 / Doc 6 §2.3.

4. Cleanup — Superseded → Doc 6 §2.7 (floors), Doc 8 CleanupService, Doc 11 §1.3/§6.

5. Log files
- Log dirs listed with view+download; viewer pane opens file contents.
- Toggleable channels: Minecraft Logs / Crash Reports / Backup & Restore Logs / Panel Activity Logs / Panel Errors+System Logs.

6. Instructions
- Content = markdown from docs folder rendered to CSS+HTML; auto-generated clickable side ToC; suppress in-file ToC in desktop mode.

7. Global UI Rules
- Pane taxonomy (purpose labels; anatomy = Doc 4 §3, Doc 10 §3.2): Nav/Header/Content/Action Pane — class `pane` + subclass + per-pane id; Pane Title Row then Pane Content cards.
- All styling/geometry/state rules: superseded → Doc 4. Nav alert indicators: superseded → Doc 10 §2.1 (nav purely navigational; state via shell notification dropdown Doc 5 + per-page status).

8. Local UI Rules
- Homepage (Doc 5): stat boxes Server Status (RAM/CPU/freq/storage), Minecraft Status (state/players/tick/auto-stop-in), Backup Stats (status/last/next/folder); Live Log Pane (4 stream channels) + RCON command input.
- Backup & Restore page (Doc 5): file-list pane (download/restore, sort, filter); sliding Restore Pane with live restore logs.

9. Initial Setup
- First run: missing config -> setup; password+confirm, MC dir, backup dir, timezone (epoch-based). Config generates env file with defaults.
- → Setup flow/settings: Doc 2 §13, Doc 5.

10. Security
- Zero-Trust: trusted-network placement reduces exposure only; every request authenticated+authorized server-side (Doc 2 §8, Doc 3 §8.1).
- RCON password regenerated per server start; expected rcon settings enforced in server.properties.
- → Full identity/authn/authz model: Doc 2 §8, Doc 6 §1.1/§2.14/§2.15/§2.16, Doc 8 Authentication/AuthorizationService.

11. Logging
- → Native log/backup pipeline (script adapters transitional only): Doc 2 §4.1, Doc 3 §5.8.
- → Audit capture: Doc 6 §0.1 Global Audit Invariant, Doc 8 §10.

12. Env File — Superseded → env holds only non-secret runtime config (paths, refresh rates); secrets/password hashes → Doc 7 §2.24, Doc 10 §2.2.

13. Error Handling & Notification System
- Errors logged + client popups. Crash: logged, notified, state crashed, process stopped.
- Missed runs: never auto-caught-up → Doc 6 §2.6.1, Doc 8 SchedulerService.
- Device identification: static IP↔DNS map from VPN; actions log IP, UI maps to name; CSV list → Doc 6 §2.13, Doc 8.
- Popup modal *content* variants (dressed in Doc 4's four structural kinds — mapping Doc 10 §3.1): Action Successful ack; Action Accepted (initiated); Password prompt (initial/protected); Action Rejected (password failed); Cleanup dry-run list; Cleanup execution summary; Error (more-details); Warnings/Prompts (opens concerned page/pane).
- Chimes: startup sound on readiness (resolver-based, never log-line-sole); shutdown sound on shutdown start.

14. Conflict Resolution — Superseded → Document 11 §3/§6 (queue/reject/preempt), Doc 8 §7 residuals. Residuals not covered elsewhere: queue position/completion pushed live (never polled); file-level restoration wins over deletion when both queued.
